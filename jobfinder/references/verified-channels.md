# 渠道方法与边界

这是可复用的观察和核验流程，不能当作任何站点本次可访问的保证。公开版本不携带历史私人搜索结果；每轮保留实际时间、查询、链接和读取状态。

| 渠道 | 读取路径 | 容易混淆的边界 |
|---|---|---|
| 企业官网 | **岗位查询词搜索** → 结果里的企业 → 逐家官网招聘入口 → 列表 → 独立岗位原文 | 总部地址不是工作地点；投递按钮不等于仍开放；名单只来自本渠道 |
| 智联 | **站内搜索** → 当前列表 → 对应详情面板或独立页 | 点击一条不等于整页；登录遮挡与已读全文分开 |
| 猎聘 | **站内搜索** → 可访问列表 → 原岗位详情页 | 卡片、搜索结果摘要只算候选；验证码不能绕过 |
| BOSS | **站内搜索** → 列表 → 详情面板 | 未登录是 JS 空壳，不是"零岗位" |
| 前程无忧 | **站内搜索** → 当前列表 → 独立岗位详情页 | 卡片标题常是纯文本而非链接，需换点法进详情 |
| 人才服务、人社及高校 | 原公告 → 雇主名称 → 岗位和报名入口 | 发布机构、转载方不能自动视为雇主 |
| 本地宝及公众号 | 原文 → 报名截止时间 → 投递出处 | 转载日期不是岗位更新时间；旧文章需重新核验 |

平台渠道的**第一手段是站内搜索**，不是外部搜索引擎。外部搜索只用于两个场景：官网渠道的岗位查询词检索，以及站内搜索受阻后的补漏。用外部搜索 `site:zhaopin.com` 命中的结果，来源记为外部搜索，不能当作该渠道站内搜索已执行。

## 官网渠道：企业名单只从本渠道查询词结果来（4.1）

官网渠道不再靠"监管企业名录/机构名单"这类目录查询起步——目录页不是岗位来源，也回答不了"这家企业是否在招"。改为三段式：

1. **查询词检索 + 研究型检索**：执行计划里的 `route=direct`（岗位查询词）与 `route=research`（研究型检索，给 `domain_search` 用）任务，每条任务一个词，不拼接同义词。research 任务解决的是"通用搜索被平台页占满、拿不到企业名"这个卡点。
2. **形成企业名单**：`official-catalog --plan <计划> --receipt <回执> --output <名单>`。只读本渠道回执，按候选**首次出现顺序**收录企业，逐条留痕剔除原因：

   | 剔除原因 | 含义 |
   |---|---|
   | `missing_task_ids` | 候选没挂在任何任务上，无法证明来自本渠道 |
   | `not_official_channel_task` | 命中的是别的任务（平台渠道任务、已删除的目录任务） |
   | `platform_url` | 链接落在招聘平台域名，且该候选挂的是 `direct` 任务（`research` 任务有豁免，但要标 `lead_only`） |
   | `no_company_name` | 目录页/聚合页，没有可识别的企业主体 |
   | `placeholder_employer` | 企业名是"某公司/猎头代招/保密"这类代称，生成不出可执行任务 |
   | `directory_page` | 候选类型是 `enterprise_directory` |

   **回执必须带 `task_ids`**：没有任务归属的候选一律按 `missing_task_ids` 剔除，进不了名单——这是渠道隔离能成立的前提，保存回执时不能漏填。

3. **逐家官网检索**：`official-plan --config <配置> --plan <计划> --catalog <名单> --output <新版计划>`，按名单顺序生成 `企业名 城市 岗位词 招聘` 任务。超出每城搜索预算的企业**不删行**，标 `budget_exhausted` 留痕。

**渠道独立性是硬约束**：官网渠道的名单只来自本渠道任务（`direct` / `research`）的查询结果；平台渠道（智联/猎聘/BOSS/前程无忧）任务发现的企业不进本渠道名单，本渠道名单也不回填平台渠道。两条线各花各的预算，各报各的覆盖。唯一的例外是本渠道自己的 `research` 任务——研究摘要常指向平台页面，这类企业以 `lead_only=true` 入名单，只当线索，必须回官网核实企业全称与在招状态。

## 站内搜索入口（2026-10-30 实测，均需登录态）

| 渠道 | 站内搜索地址 | 上海城市参数 | 备注 |
|---|---|---|---|
| 智联 | `https://sou.zhaopin.com/?jl=<城市码>&kw=<词>` | `jl=538` | 会 302 到 `www.zhaopin.com/jobs/?jl=..&kw=..`，正常 |
| 猎聘 | `https://www.liepin.com/zhaopin/?key=<词>&dqs=<城市码>` | `dqs=020` | **必须用 `dqs`**；`city=020` 无效，会返回全国 |
| BOSS | `https://www.zhipin.com/web/geek/job?query=<词>&city=<城市码>` | `city=101020100` | 未登录返回空壳 |
| 前程无忧 | `https://we.51job.com/pc/search?jobArea=<城市码>&keyword=<词>` | `jobArea=020000` | 城市与关键词都直接生效，匹配最准 |

**已知坑位（都踩过）**：

- **关键词相关度**：智联、BOSS 对"高级薪酬总监"这类长词按松散相关度召回，会把"总监"降权，返回薪酬专员、HR 外包（9-11K）。猎聘次之，前程无忧最准。遇到这种召回，换更短的核心词（如"薪酬经理"）或叠加原生筛选，不要直接宣布"该渠道没岗位"。
- **薪资筛选够不到高档**：智联薪资筛选最高档只到 15K-25K，用不了 4 万这条线；BOSS 的"薪资待遇"下拉在自动化坐标点击下不展开。这两家不能用薪资筛选兜底，只能逐卡读。
- **卡片标题不是链接**：前程无忧列表卡片标题是纯文本，坐标点击只会选中文字，不会进详情。要拿详情链接，走下面的「详情反查」。
- **虚拟滚动**：猎聘列表是虚拟滚动，鼠标滚轮或 PageDown 后可视区会空白，翻页不可靠。只能读首屏，或改用带 `dqs` 的分页 URL。
- **反爬白屏**：猎聘连续请求后可能整页空白，刷新可恢复；仍空白就记 `blocked`，不要当成零结果。

**本地宝（`bendibao_web` / `bendibao_wechat`）**：本轮才接入计划层，站内入口与城市参数**尚未实测**。首次使用须先打开对应城市站点确认地址与检索方式，不要写死 URL；公众号渠道只能靠检索可见内容，拿不到后台列表，覆盖必须标注为不完整。

## 通用搜索的上限与查询词写法（2026-10-30 实测）

- **一次检索固定 5 条**。短词、长尾词、`site:` 限定、否定 `-site:` 四种写法都返回 `Found 5 results`，不存在靠改写拿更多条数的办法。计划里的预算不能按"一次搜索 N 条"估算。
- **信息密度差一个量级**。短词 `上海 薪酬绩效总监 招聘` 的 5 条里 4 条是聚合页（猎聘城市聚合页 13 条卡片、BOSS 岗位聚合页各 7–8 条卡片），一次检索可覆盖 40+ 卡片；长尾模板 `上海 高级薪酬总监 社会招聘 招聘 官网 工作地点` 的 5 条几乎全是单岗位详情页，可用只有 1–2 条。**查询词要短**，"官网""工作地点""社会招聘"这类词不产生过滤作用，只是把结果稀释成详情页。
- **`site:` 单域限定有效**：`site:jobs.51job.com 上海 高级薪酬经理` 命中全部落在 51job，还能直接命中职场文库的月度聚合页（单页 30+ 条岗位带薪资）。站内搜索失败时可作兜底。
- **否定 `-site:` 无效**：实测加 5 个否定站点后，返回结果依旧全是 liepin / 51job / bebee。这就是官网渠道名单常常为 0 的机制原因——通用搜索无法把平台域名排掉，除非用户直接给企业名单，否则改用 `extend-plan --catalog`。

## 列表页直读（平台渠道主路径，2026-10-30 实测，2026-10-31 升为主路径）

通用搜索固定 5 条，但**列表页一次能拿 20–40 条**，还带薪资、发布日期、岗位直链和职责原文。这条路只读网页、不依赖登录态，是智联/猎聘/BOSS/前程无忧的**第一手段**；站内搜索降为兜底。

| 入口 | URL 形态 | 单次产出 | 翻页 |
|---|---|---|---|
| 前程无忧 职能分类页 | `https://jobs.51job.com/{城市拼音}/{职能类目拼音}/p{页码}/` | 每页 20+ 条，含职责原文与 `jobs.51job.com/...` 岗位直链 | `p1/` `p2/` `p3/`… 逐页递增；实测 `p1/` 与 `p2/` 内容不重复 |
| 猎聘 城市×职能聚合页 | `https://www.liepin.com/city-{城市缩写}/career/{职能类目拼音}/` | 单页 40+ 张卡片（岗位/薪资/地点/经验/学历/公司规模/联系人） | 无；虚拟滚动抓不到下一页 |

实测样本（上海「薪资福利经理/主管」类目 `xinzifulijingli`）：`p1/` 命中嘉顺达 2.5-3万、美年健康 2-2.5万·14薪、恒瑞 3-4万·13薪、迈图 2.1-2.8万、华珵 6-7万·15薪、味好美 3-4万·13薪、扬子江 4-5万、示优 Payroll Manager 3.5-6.5万、移远 2-3.8万；`p2/` 是另一批（C&B Supervisor、北羽自动化、上海家化、蔻沣、思源电气等）。

**在计划里怎么出现**：

- 一条 `route=browse_list` 任务 = 一页，`query` 就是该页 URL，`browse_url`/`browse_page`/`covers_roles` 留痕。执行时按 `query` 原样请求，回执里 `search_tool` 写实际读取方式（WebFetch/浏览器）。
- **一页记 1 次搜索预算**。这样做是为了让"预算用了多少"能和任务数对上账：如果页数不记账，翻 50 页和翻 1 页在报告里长得一样。HTTP 请求数照旧另计（默认不限）。
- 渠道/城市/岗位词三者任一没有实测组合，就**不生成 browse_list 任务**，退回 `route=channel_search` 站内搜索——不猜 URL，猜出来的链接会成为假证据。
- 当前实测覆盖：`51job` + 上海 + 类目「薪酬福利经理」（5 页）；`liepin` + 上海 + 类目「薪酬绩效总监」（1 页，不可翻页）。新城市/新类目须先人工确认 URL 有效，再写进 `planning.BROWSE_CITIES` / `BROWSE_CATALOG`。

**限制**：

- 分类页按**职能类目**组织，不是关键词检索。类目拼音须按站点实际类目拼（薪资福利经理/主管 → `xinzifulijingli`，薪酬绩效总监 → `xinchoujixiaozongjian`）。关键词级检索仍需站内搜索，或 `site:` 兜底。
- WebFetch 会在页面底部截断，拿不到分页控件本身，只能按 `p{n}` 约定逐页请求。
- 猎聘聚合页岗位多为猎头代发，企业名常显示「某上海…上市公司」，与平台渠道的匿名岗一样处理：**不能当企业名写入企业库**，也不能回流官网渠道名单。

## 研究型检索：给官网渠道找企业名（2026-10-31）

`domain_search`（托管研究型检索）一次能跨十几个来源，返回"哪些企业正在招这个岗位"的合成摘要 + 来源链接，比通用搜索的 5 条上限覆盖广得多。它不做岗位发现，只做**官网渠道第一段**：产企业名。

- 计划里的 `route=research` 任务就是给它用的，每岗位词一条。
- 它返回的是**摘要**，不是原文。岗位条目不能直接入库，只能提取企业名。
- 摘要里的来源链接大多落在平台域名。这类候选允许进企业名单，但必须标 `lead_only=true`，企业全称、在招状态、岗位城市都要回官网核实。
- 企业名是代称（某公司/猎头代招）的一律剔除，生成不出可执行任务。
- 成本不在调用本身，而在**每条线索还要回原文核一遍**；所以它只适合"缺名单"时用，不适合当常规岗位发现通道。

**实测（2026-10-31，query「研究上海地区哪些企业在招聘高级薪酬经理或薪酬绩效总监岗位」）**：一次返回带来源链接的合成摘要，可确认具名的雇主 25 家以上，包括妙可蓝多、广泽乳业、三生制药、联合利华、妮维雅、无印良品、水羊股份、凯莱英、药明生物、勃林格殷格翰、开润股份、歌尔股份、思格新能源、南亚新材、菲利华、鼎捷软件、舒华体育、中国太平洋保险、基煜基金、东方财富、美腕、申通快递、唐纳森、Warner Bros. Discovery 等；同时混入"某上海食品/饮料/酒水上市公司""某科创板生物医药企业"等猎头代称若干条（按 `placeholder_employer` 剔除）。对比之下，同类通用搜索一次只有 5 条且全是平台页——这就是它值得用的地方。

但它同时暴露了三个必须核的点：① 摘要里的薪资和"是否在招"是二手转述，同一岗位在猎聘标 35–60k、企查查标 40–60k，口径不一致；② 岗位实际工作地可能与发布方所在地不同（凯莱英副总监岗页面显示天津）；③ 集团/子公司主体混用（东方财富岗实为新夏晖发布）。这些都只能回官网或原页核实，不能拿摘要当结论。

## 官网招聘页：用浏览器读（2026-10-31 实测）

官网招聘页绝大多数是前端渲染（Vue/React SPA），`WebFetch` 静态抓取只能拿到空壳或企业文化文案。**用浏览器打开就能正常渲染**，这是官网渠道第三段（逐家企业核实）唯一可靠的手段。

**能拿到什么**：岗位名、工作城市、职位类别、全职/实习、发布日期、详情链接。DOM 快照是"一行一个岗位"的干净结构，可直接解析入库。

**拿不到什么**：**薪资**。实测 B 站、米哈游两家官网的岗位卡片和详情均不显示薪酬区间——国内企业官网普遍如此。因此官网渠道的产出是「该企业在招 + JD 原文」，不是可参与薪资筛选的岗位条目：入库时 `salary_raw` 留空，由核心评估给出 `salary=UNKNOWN`、整条落 REVIEW，**不得按"薪资未达 4 万"排除**，也不得拿平台渠道的薪资替官网岗位补值。

**URL 参数可直接构造，不必模拟点击**（这是效率关键，实测均成立）：

| 站点形态 | 检索/翻页 URL | 实测 |
|---|---|---|
| 自建路径式 SPA | `jobs.bilibili.com/social/positions?name=<关键词>&type=3`，翻页加 `&page=2` | `?page=2` 返回完全不同的 10 条；列表共 48 页/476 岗 |
| 自建 hash 路由 SPA | `jobs.mihoyo.com/#/position?jobName=<关键词>` | 搜「薪酬」返回 2 条（薪酬专家·上海·综合类、AI研发招聘专家） |
| **Moka**（第三方 ATS） | `app.mokahr.com/social-recruitment/<slug>/<id>#/jobs` | 众安：列表 DOM **直接带岗位职责前几行**，是全类形态里唯一能拿到职责原文的 |
| **北森 zhiye**（第三方 ATS） | `<brand>.zhiye.com/social/jobs` | 三生制药：222 个在招岗位、按城市/发布时间筛选、岗位带编号（J17508） |

**找入口比读页面更难**。企业官网的招聘入口很少在 `/careers/`（猜这个路径大面积 404）：复星是 `/join/`、歌尔是 `/join/culture.html`。正确做法是**先读官网首页 DOM，找含"加入/招聘/careers/join"的链接**，再进；国内企业大量把岗位库托管在 Moka 或北森，官网只留一个外链，甚至只留"司机加入"这类业务入口（货拉拉）而员工招聘入口完全不在站内。

**实测产出量（2026-10-31，对 20 家名单企业逐家核实）**：能打开且有公开岗位库的只有 3 家，其中 2 家命中薪酬岗（众安 1 条、B 站 1 条），1 家 222 个在招岗位里搜「薪酬」为 **0**（三生制药，可确认该企业确实不招）；另 3 家官网无职位列表、1 家岗位库需账号登录、7 家找不到招聘入口、6 家仅做域名探测。**薪资披露 0 家**。单家企业官网的薪酬类岗位供给本就极少，官网渠道只能当"在招信号 + JD 原文"用，不能指望它补岗位量。核实明细见工作区 `data/discovery/official-verify-20261031.json`。

**已知坑**：

- 详情页点击经常不触发跳转（B 站、米哈游都复现），`cua_click` 与 `dom_cua_click` 均可能失效；要么改用详情 URL 直接导航，要么只取列表级字段。点击失败**不代表页面没有该岗位**，别误记成零结果。
- 部分企业招聘站域名已失效（叮咚买菜 `job.100.me` 返回错误页），要先开首页确认存活，再决定是否按官网处理。
- 有些企业确实没有公开岗位库（实测歌尔、水羊、南亚新材、复星、货拉拉、七牛云、叮咚买菜、药明生物），浏览器也救不了——这类企业只能标「官网无公开岗位库」，岗位信息回平台渠道取。注意**不能凭一次没找到就下这个结论**：众安曾因官网首页无招聘入口被判"无岗位库"，实际它的社招挂在 Moka 上、有 30+ 在招岗位，入口藏在首页导航深处。判定前至少试过"首页 DOM 找链接 + Moka/zhiye 子域名"两条路。
- 滚动与点击类动作可能**回执超时但实际已执行**，判断是否生效要看截图或 DOM，不要凭超时结论重试到死。

## 详情反查（2026-10-30 实测可用的四条路）

列表卡片只到"有岗位"这一层，要拿职责原文和投递链接必须反查详情。按成本从低到高：

1. **职位分类页**：`https://jobs.51job.com/shanghai/<职能类别拼音>/`，例如 `xinzifulijingli`（薪资福利经理/主管）。服务端渲染、直接带详情链接，一次拿 20 条，是性价比最高的一步。已知类别：`xinzifulijingli`、`jixiaoguanli`。
2. **公司职位页**：`https://jobs.51job.com/all/co<企业码>.html`，锚点文本含职位名 + 薪资 + 地点 + 学历 + 经验。缺点是按发布时间倒序，几百个岗位的公司在里面翻很慢——企业码可从站内搜索页的卡片 DOM 直接取到。
3. **职场文库聚合页**：`https://wenku.51job.com/shanghai_jobs/<年月>/<职能类别拼音>/`，带 **发布日 + 学历 + 经验 + 详情链接**，是补"发布时间"字段的可用来源（列表卡片通常不显示发布日）。
4. **按"公司名 + 岗位编号"做网页检索**：命中率高于在列表页翻找，常用于拿带编号的岗位（如 `J23958`、`MJ006291`、`A08515`）。

详情页规范地址是 `https://jobs.51job.com/<城市>-<区>/<jobid>.html`，可被无状态抓取直接读取，无需登录。

**反查必须核对的三件事**（这三处本轮都踩到了，不核就会错）：

- **同一岗位多渠道报价可能不一致**：移远 `MJ006291` 在猎聘标 50-65k、前程无忧同一编号标 2-3.8万，另有 3-4万 一条。发现差异记冲突、写进待确认说明，不能挑高的那条当结论。
- **经验口径可能不是同一件事**：华珵详情页写"5年以上团队管理经验"，卡片标"10年及以上"，一个是管理年限一个是总工作年限，不是矛盾，别当成数据错误改掉。
- **同一 JD 会跨渠道挂载**：恒瑞薪酬福利经理在前程无忧标 8年及以上、在智联标 5-10年，JD 逐字相同。用岗位编号或 JD 原文做锚点识别为同一岗位，避免当成两个机会重复投递。

未取得详情页原文的岗位，`evidence_level` 记 `onsite_list`、`details_complete=false`，只能进 REVIEW，不能当 MATCH 交付；投递链接必须如实标"待补"，不能用工整的猜测链接填满表格。

先把岗位相关名称列出来，再按城市、岗位词、渠道执行；渠道的实际尝试、失败、完整详情、待确认和排除数分别报告。用户指定多个渠道时，不能以一个渠道的结果冒充全部渠道已执行。

动态站点按[浏览器采集](browser-collection.md)保存可见原文。智联整页操作按[zhaopin-onsite.md](zhaopin-onsite.md)。公共工具不可用时保留限制与接续位置。
