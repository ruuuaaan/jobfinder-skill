# 招聘栏目遍历与恢复（新任务 4.0，旧任务 3.9 兼容）

目标是覆盖选定招聘栏目或原生筛选范围。已有入口复用、失效回退、来源分类与网络安全沿用3.6。不是先强制逐岗位词搜索；读取后的原文岗位统一匹配。范围以实际入口、栏目和选用的筛选分支记录，不能把单个栏目完成称为企业所有招聘渠道完成。

## 原生筛选

城市和用户已填招聘类型优先；只使用实际存在且与条件等价的选项。Python当前识别带data-filter或aria-label的城市/工作地点、招聘类型容器内的真实a[href]选项，要求覆盖全部目标值，然后读取这些原文URL；不构造参数，不发送表单，不执行JavaScript。多城市/多类型分支分别遍历，未取得等价选项时读原列表后判断。不会强制输入关键词。

新规则“我的学历=本科”按统一学历规则比较是否满足最低门槛，包含明确学历不限；单选“本科”并不等价。旧配置仍按保存的比较方向。当前核心保守地在读取后匹配学历，不自动套用学历下拉框。助手在浏览器使用原生学历选项时必须覆盖用户接受的全部层级、未知及明确不限的配置语义；无法证明等价就不施加这个原生筛选。网页选项不能补成岗位自身的学历或地点。

其他选择框、提交表单、动态城市联动属于获准浏览器操作协议。助手保存原URL、可见选项、所选标签和值、对应用户条件、操作时间和结果范围；只使用页面实际给出的动作。没有适用筛选时直接读取完整栏目，仍可在本地统一匹配。

## 静态列表与详情

解析本页岗位与继续翻页同时进行。支持实际a链接中的rel=next、下一页/Next/加载更多；分页链接与详情链接分别排队。详情页上的上一条/下一条或分页不作为招聘列表翻页。显式pagination_urls须仍在原页出现且同域，已移除最多3个限制；所有自动链接均受逐URL/窄路径策略、robots、重定向和原请求预算约束。

相关或不确定岗位补读观察到的详情URL（包括JobPosting.url）。列表已明确证明实际工作城市不符时可跳过详情；职责范围排除须有助手原文判断证据。标题不含精确关键词只能保留待核查，不能据此跳过详情或直接排除。正文解析仍使用已有适配器，未支持的详情保持未完成。

Candidate.role_decisions每项包含url、decision（related/out_of_scope）、role_keywords（当前原词）、rationale、quote及content_hash。核心验证当前页面哈希、摘录和岗位URL关联，将证据写入Job.role_review；多岗位页还须摘录含该岗位标题或提供对应source_id，不能将同页一岗判断套给其他岗位。语义由助手负责。无充分判断且标题未命中时为UNKNOWN/REVIEW。不同岗位条件重算时旧判断不能直接沿用；没有通用自动语义分类器。

判断列表末尾需要禁用的“下一页”、明确“第N页 共N页”，或适配器返回总数与本范围唯一岗位ID数量一致等证据。没有下一页链接本身不证明完整；单页零新增但仍有下一页继续读取，连续3页没有新增原始岗位或详情链接则以no_loading_progress保留未完成。加载进展与匹配数量分开，不相关的新岗位也算进展。循环、重复响应、访问错误/受限、预算耗尽、动态加载未完成均记录未完成。列表覆盖list_complete和相关详情details_complete分开；complete只在两者及异常检查都通过时成立。即使已有匹配岗位也继续遍历本栏目与同批已选的其他招聘栏目。

## 动态网站边界

- Moka：解析原页init-data；若当前页面记录未覆盖jobStats.total，且没有实际HTML下一页链接，列表仍不完整，需浏览器或后续经审核适配。已审核的逐岗位详情接口可继续补读相关/未知岗位，沿用总请求预算，不再固定只读4条；授权/429等错误停止同一接口后续请求并保留待办。
- “加载更多”按钮无可读URL、滚动加载、编码响应及其他动态外壳：HTTP遍历保留requires_browser等未完成原因。已观察的动态DOM列表、单iframe、分页及新标签可按[浏览器采集](browser-collection.md)执行；虚拟滚动等未覆盖结构仍需辅助读取。

助手使用获准浏览器时，每次加载更多/滚动后记录操作、时间、加载前后唯一岗位数、观察到的下一步控制及原文证据。零新增不能单独当作结束；须看到明确无更多/末页或完整数量依据。出现错误、验证或预算不足即保留当前位置和待处理项。脚本回执可经process-browser校验并产生独立浏览器覆盖结论；其他原文辅助读取按SKILL的Job/Evidence协议交接。两者不能直接把旧Python HTTP进度改成已完成；resume-traversal仍只恢复HTTP原生队列。

## 进度与预算

默认每城40次实际搜索，企业/HTTP总量null不限；按城市及候选轮流推进一个列表/详情步骤，每步、开始和异常退出保存进度。单步所需robots、重试、导航仍有限。浏览器遵循同样范围、轮转与停止规则，但没有接入Python自动计量或恢复；实际请求未知时记录“未计量”，有限预算无法核实时暂停。详见[预算契约](budget.md)。

每次输出traversal-progress.json（traversal-run-1），包含配置/规则指纹、states、既有jobs和budget_used。每个范围保存candidate、筛选分支、visited（URL/类型/哈希/快照/时间）、pending分页和详情、岗位ID、原文岗位、终止证据、异常原因、跳过详情依据及完成状态。所有失败和未审核链接保留；不会将其算已访问成功。

```powershell
python -m jobfinder resume-traversal --config <原配置> --input <traversal-progress.json> --policies <当前审核策略> --output outputs/real/<新目录>
# 只有明确决定开启新一轮预算时：
python -m jobfinder resume-traversal --config <原配置> --input <traversal-progress.json> --budget-mode new_run --policies <当前审核策略> --output outputs/real/<新目录>
```

默认remaining延续原运行已消耗的请求/搜索/企业额度，耗尽仍不执行；new_run显式按相同配置重新分配本轮预算，结果记录此语义。两者均保留已完成页面、岗位与原证据时间，只处理待办；未重新读取的范围报告access_status=cached_progress，实际待办请求单独报告。预算耗尽前尚未读取的其他栏目/企业也保存为待处理范围。恢复隐式路径授权时重新核对原快照哈希和当前策略，不凭进度文件扩大权限。缺失快照、配置指纹改变会拒绝或保留未完成。已完成页遇到后来新增职位需要另行refresh，这是刷新而非继续旧覆盖。

循环/无末页证据/持续无加载进展等结构性缺口不能靠重复恢复自动消除，需浏览器核对或重新刷新该范围。当前不支持的待办类型标记unsupported_progress，不能当作通用GET继续执行。3.9 旧任务保持原指纹，4.0 不静默重解释旧进度；明确变更条件后使用新计划并保留原文件。新输出合并同版本旧进度岗位，完整详情替换同岗位列表占位，随后沿用去重/evaluate及Excel/JSON导出；不覆盖历史输出文件。示例：configs/example.traversal.json；回归：tests/test_traversal.py、tests/test_budget.py。
