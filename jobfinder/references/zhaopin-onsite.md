# 智联站内搜索与整页核验

适用于用户要求在智联站内搜索，或继续核验已有智联结果页。使用当前 computer-use 浏览器协议操作正常页面；本流程是浏览器辅助读取，不是独立爬虫或已接通的智联API。外部搜索引擎的 `site:zhaopin.com` 查询另记来源，不计作站内搜索。

## 输入和范围

- 沿用本轮确认的城市、岗位词组和学历比较方向；薪资、经验、招聘类型未填就不筛选。先按主技能展开岗位词，但实际每次只提交一个词或原站明确支持的组合，不将所有别名拼成同时必需。
- 继续任务保留原配置、指纹、已消耗搜索次数及已读证据。记录实际提交的词；计划中的同义词未搜索就写 `not_run`，不写“零结果”。查看同一结果页的候选详情不算新搜索。
- 渠道验证默认至少完成一个可访问页面或首批列表的逐项核验；用户明确只要单条样本时才按样本范围停止。一页核验是最小验收，不是结果条数上限。完整搜索仍按预算继续实际分页和词组，不能完成一页后称全部检索完成。

## 站内查询与筛选

1. 绑定用户指定或本任务已有的标签，确认实际URL和页面内容。已有正确结果页就从该页接续；否则从首页切换目标城市，核对城市站后在“搜索职位、公司”框输入岗位词，提交搜索。
2. 城市切换、搜索、详情可能新开标签。点击前后对比标签清单，核对新标签的URL和页面内容，不继续读取旧页。清单更新有延迟时再次观察；工具超时后先检查动作是否已生效，不立即重复提交或创建标签。
3. 记录提交后的真实结果URL、城市、关键词、登录状态、排序状态、读取时间和筛选有效性。不得凭查询参数臆造城市代码；不要为了匹配历史截图而擅自改变排序。
4. 原生筛选只用实际存在且与用户条件等价的选项。“本科”单选不等于“本科及以上”；没有等价多选时按详情逐岗判断。点击选项弹出登录且结果未变化，记录 `requires_login_not_applied`，不能说筛选成功。
5. 用户暂不登录时关闭可关闭的弹窗，保留并继续读取当前公开候选。某个筛选或“查看更多结果”需要登录，不证明当前每个候选的详情也无法读取。实际遇到登录、验证或拒绝的具体动作单独记录，不能把未尝试写成受阻。

## 本页逐项核验

先保存本页全部可识别卡片，建立稳定清单：页/批次、序号、企业展示名、原岗位名、列表地点/学历/经验、薪资显示状态、已有链接。出现企业就按主技能 `record-discovery` 入库；企业展示名不自动扩写为法律全称，未知官网留空。

对清单逐条执行，不因标题不像目标岗位就跳过：

1. 点击该卡片的岗位标题。相同或相似标题必须先以企业及卡片范围定位；不能使用全页第一个同名文本，也不能把右侧默认选中的岗位当成当前候选。
2. 等待正文切换，核对详情区域的独立岗位主标题、该区域内的企业以及真实详情链接。只在完整页面其他位置找到同一企业名不算绑定成功。标题混入薪资、图标文案时核对独立标题文本，不能宽松包含即接受。
3. 读取对应详情面板内的职责、任职要求、地点、学历、经验、薪资、招聘类型/毕业年份、截止日期和投递方式。章节可能用 `text`、`generic`、列表项呈现，且要求可能先于职责；按实际章节提取，不只抓一种节点或固定顺序。缺失字段留未知。
4. 从该面板“查看更多职位信息”等真实链接取得独立岗位URL/岗位编号。企业介绍链接不是投递链接。只取得URL，不代表独立页已打开；原页“立即投递”按钮仅证明有入口，不证明登录后提交可用或岗位仍开放。
5. 面板已清楚绑定具体岗位且显示正文，可作为原岗位证据，不强制每条再开一个独立页。面板缺内容、对应关系不清或用户要求独立页验证时，沿真实详情链接打开并再次核对企业和主标题；如新开标签，按当前工具规则处理。
6. 每条处理后保存快照、时间、链接、字段摘录、SHA256和状态。正文切换失败先有限重试并重新核对；仍失败记具体问题，继续下一条。中断恢复按清单处理未完成项，不重复覆盖旧证据时间。

2026-10-26观察到卡片容器 `.job-card`，可在该容器内按企业链接和精确岗位文本限定；这只是当次DOM事实。后续先观察页面再使用定位器，不能把旧选择器、标签ID、查询身份参数或岗位编号固化成通用适配器。浏览器动作和读取曾各耗时约21秒；拆成可检查的小步并留足工具超时，不额外固定睡眠，不将传输超时视为网站拒绝或零岗位。

## 内容与匹配规则

- 原页出现“登录查看完整内容”，保留可见职责/要求，设 `details_complete=false`。没有该提示也要检查职责和要求是否读完，不能仅因没有登录弹窗就判完整。申请按钮、招聘者在线、企业总在招数都不单独证明本岗位开放；未核实设 `open_status=UNKNOWN`。
- 详情不完整或在招未知通常为 `REVIEW`；已有明确不符条件时仍由核心判 `EXCLUDED`。薪资不设筛选时，薪资隐藏本身不是排除或待确认的唯一理由。
- 隐藏薪资不能从相似职位补齐。岗位标题中的金额只按标题信息保留，不补币种、周期或税前税后口径。
- 页头和正文的经验、学历、地点不一致时保留双方原文和 `conflicts`。正文明确实际工作地时据其判断并保留冲突；含多个工作地点而归属不清时待确认，不用公司所在地代替。
- 岗位职能以标题和实际职责一起核对。FMBP、财经BP、财务计划分析可能属于同职能；“销售业务BP”也可能承担预算和财务分析。相反，共享中心负责人或销售管理可能超出财务BP范围。按当前用户范围与原文判断，不维护公司/岗位名硬编码白名单。
- 标题未命中时用有证据的 `role_review` 交给核心：保留原 `role_keywords`、`related/out_of_scope/unknown`、原文摘录、快照哈希和理由；提交前验证摘录确在该岗位正文、哈希一致、岗位与证据URL关联正确。不改原标题或直接手写MATCH/EXCLUDED。
- 同一公司不同岗位编号分别保留，例如优才生和有经验的财务BP。毕业年份、专业、证书、驾龄等写入要求；本轮未限定招聘类型时不自动排除校招，也不假设用户满足应届资格。

## 证据、核心与输出

保留三种不同计数：列表候选数、详情面板读取数、独立页读取数。具体文件名可沿用本轮约定，至少能恢复以下信息：

| 记录 | 必要信息 |
|---|---|
| 搜索日志/候选清单 | 实际查询词、城市、搜索时间、实际结果URL、原配置关联、全部卡片及初始链接；未执行词明确标记 |
| 逐项核验台账 | 页/批次与序号、企业及标题、是否尝试、面板/独立页、岗位URL/编号、读取时间、快照路径/哈希、限制或错误 |
| 字段与结论 | 原文摘录、来源、职责/要求完整性、开放状态、冲突、职能证据及核心匹配结论 |
| 完成记录 | 本页应处理/已尝试/成功读取/受阻/未尝试数，待处理项、分页和筛选状态，明确覆盖范围 |

`Evidence.source_url` 写实际读取页面URL；读搜索页侧边面板就记录搜索页URL及选中岗位上下文，`Job.detail_url/application_url` 可保存该面板实际提供的岗位链接。只有确实打开独立页，才把该页计入独立页读取及其原文证据。候选取得新详情链接后补充回执并入库，不重写初次发现时间或虚增搜索次数。

平台记录使用 `source_channel=zhaopin`、`source_type=platform`、实际 `browser_visible_dom` 方法。当前 `process-browser` 仍按 `official_career` 处理官网来源；在该入口未支持平台来源前，采用主技能允许的辅助读取方式，逐字段建立 `Job/Evidence`，验证绑定后调用已有 `deduplicate/evaluate`，使用当前表格技能导出。不能为复用官网入口而把智联伪装成企业官网，也不把浏览器读取记成Python HTTP成功。

匹配及待确认合并为一张十列表：公司名称、岗位名称、岗位描述、薪资水平、投递链接、工作地点、学历要求、经验要求、岗位来源、待确认说明。最后一列注明“公开详情可读，全文/在招待确认”等实际限制；只有列表时明确“待确认：仅列表信息”，不能称已读详情。排除项保留在配套报告和JSON，记录原因；只见搜索摘要仍是线索，不冒充原岗位。

导出后核对行数、去重、源数据、可点击真实链接、筛选、冻结表头及可读性。仅公式错误扫描无报错不够：本次表格工具将 `HYPERLINK` 渲染成“not implemented”文字，后改成原生超链接并核对目标地址。按当前表格技能允许的方式处理缺失能力，检查最终文件和预览，不把该次故障固化成所有运行时的限制。正文证据、链接可达和投递提交验证分别说明。

## 完成和接续

本页每条均已尝试且有终态，才能报告“本页逐项核验完成”；成功读取数和受阻数仍单列，受阻不等于读到正文。存在未尝试项、列表滚动未结束或页面循环，保存 `partial` 和接续位置。网页只提供未登录首批而无分页时写“首批公开列表”，不虚构页码或末页。

正常可访问的真实下一页按任务范围和预算继续。“登录查看更多相关职位”时记录更多结果未验证；用户暂不登录则交付公开范围，不反复要求登录。不能因此跳过本页已可访问的其他岗位，也不把一页数量当成全站总数。

## 证据边界

本方法源于历史页面观察，站点界面及登录要求可能变化。公开版本不附带个人搜索记录；每次运行重新观察页面、保存真实证据和实际覆盖范围，不使用历史计数或结论。

## 已知限制（2026-10-30 登录态实测）

- **关键词相关度偏松**：站内搜"高级薪酬总监"会返回薪酬绩效主管、人事专员、HR 外包等岗位（8-18K），“总监”被降权。判断召回是否可用，看首屏是否出现目标职级，而不是看命中总数。
- **薪资筛选够不到高档**：筛选面板最高档只到 `15K-25K`，无法直接表达"4 万以上"。遇到高薪门槛，不能靠薪资筛选兜底，只能逐卡读薪资原文。
- **职位类别层级深**：`职位类别 → 人事/行政/财务/法务 → 人事 → 人力资源经理/主管` 是三级菜单，坐标点击容易落到相邻项（误选"人力资源专员/助理"会把结果拉向基层岗）。点击后必须回读 URL 里的 `jt` 参数确认类别码，再判断结果是否合理。
- 登录态失效的最快识别信号仍是薪资显示"-元"。
